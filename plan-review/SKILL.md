# 引っ越しプランのレビュー

既存の計画を本人の目的と資料に照らして検証し、実行に影響する問題と必要な確認を示す。計画の作り直しや一般的な引っ越しチェックリストの提示だけでレビューを代替しない。

## 1. 対象と確認範囲を把握する

- ユーザーが指定したチャットの記述、ファイル、フォルダを対象にする。入力例のパスや参考リンクを、指定された対象として扱わない。
- 対象が不明なら資料の所在を確認する。別チャットの計画は、利用可能な読取機能で内容を確認してから扱う。
- フォルダは先に資料を一覧化し、計画、日程、費用、契約条件、本人の希望など、判断に必要な資料から読む。大量の資料では関連性に基づいて範囲を絞り、その範囲を報告する。
- テキスト・Markdownを基本とする。他形式は利用可能な読取機能で確認し、未読・読取不能・リンク先未確認を区別する。
- 重要な情報にはファイル名と行番号・見出しなどの出典を付ける。チャットの場合は該当する発言を特定できる形で残す。
- 資料間の食い違いを残し、更新日時だけで正しい記述を決めない。

## 2. 本人の要件と計画を整理する

本人の目的、優先順位、避けたいこと、予算、期日、生活上の制約を必要な範囲で抽出する。「明示された希望」「推測」「要確認」を区別し、推測を確定した希望として判定に使わない。

必要に応じ、退去・入居・鍵受領・搬出・搬入の日程、費用、担当者、予約や手続きの状態を整理する。希望日、仮予約、確定日を区別する。各行動の前提条件と依存関係を追える粒度にする。

情報が足りなくても、確認できる部分のレビューを進める。質問は、回答によって実行可否や重要な判断が変わるものを優先する。

## 3. 引っ越しの整合性を確認する

以下は検討の観点であり、すべての引っ越しで必須の作業ではない。本人の状況に当てはまるものを使う。

| 観点 | 確認する関係 |
| --- | --- |
| 目的・制約 | 計画が本人の希望、予算、期日、仕事や生活上の制約と両立するか |
| 退去と入居 | 退去期限、入居可能日、鍵受領、立ち会いの順序が成立するか。空白期間の滞在先・荷物保管や、重複期間の費用が必要なら含まれているか |
| 搬出と搬入 | 鍵受領や搬入許可より先に荷物が到着しないか。作業時間、移動、本人や関係者の立ち会いが両立するか |
| 準備・予約 | 業者の手配、荷造り、処分、清掃などが後続作業までに完了するか。希望と予約確定を混同していないか |
| 建物・荷物 | 当てはまる場合、搬入経路、大型家具、車両、エレベーター、作業可能時間などが計画と両立するか |
| 生活の継続 | 電気・ガス・水道・通信、必要な家具や日用品などが、本人の生活開始条件を満たすか |
| 手続き | 本人に該当する住所変更、契約変更、郵便、勤務先などの手続きについて、必要性・期限・準備の確認があるか |
| 費用 | 初期費用、運搬・処分費、重複家賃などに二重計上や漏れがないか。総額だけでなく支払時期と資金が両立するか |
| 変更への対応 | 未確定の契約や予約に後続作業が依存していないか。遅延が実行を阻害する場合に、対応や余裕があるか |

具体的な契約条件や建物のルールは対象資料を根拠にする。法令・制度・手続きの期限、料金、営業時間など、外部の最新情報が判断に必要なら、該当する地域・事業者の公式情報を確認して出典を付ける。確認できなければ条件付きの判断または情報不足とし、一般的な慣行で確定しない。

資料に書かれていないことだけを理由に、作業未実施や抜け漏れと断定しない。目的達成に必要である根拠と、計画に含まれていないのか記録がないだけなのかを区別する。

## 4. 独立レビューを行う

主担当は、サブエージェントが利用可能なら別のレビューアに一巡の独立レビューを依頼する。独立レビュー担当としてこのスキルを渡された場合は、自分で元資料を検証して主担当に報告し、さらにレビューを委任しない。受け渡す情報は次のとおり。

- ユーザーの元の依頼と希望、レビューの対象範囲
- 元資料を参照できるパスまたは該当する原文と出典
- 整理した要件と計画、明示・推測・未確定の区別
- このスキルの判断基準

主担当の指摘、総合判定、疑っている箇所は先に渡さない。レビューアには、要件の整理が元の希望に合うかも確認し、重要な指摘は元資料に戻って検証するよう依頼する。

実行できない場合は主担当による確認を続け、独立レビュー未実施と明示する。自己再読を独立レビューとして報告しない。

## 5. 指摘を統合して修正案を示す

各指摘を元資料と本人の目的に照らして採否判断する。重複はまとめ、別の方法を好むだけの指摘を不整合として採用しない。

指摘は次の区分を使い、該当箇所・根拠・影響・修正案または確認事項を付ける。優先度は実行への影響と対応期限で判断する。

- **矛盾・不整合**：明示された条件が両立しない、または手順が成立しない。
- **抜け漏れ**：目的達成に必要な行動・準備・条件が計画から欠けている。
- **情報不足**：判断に必要な情報を確認できない。
- **改善提案**：成立する計画を、より本人の目的に合う形にする案。

修正案は元の資料とは別に提示する。元資料の編集は依頼された場合に行う。修正によって変わる日程・費用・依存関係を再確認する。基本は一巡とし、情報不足を仮定で埋めてレビューを繰り返さない。

## 結果の提示

結論を先に述べ、本人が次の行動を決められる形で、以下を必要な詳しさで示す。

1. 総合判定と、理解した目的・重要な条件
2. 確認した資料・確認範囲・未確認資料、独立レビューの実施状況
3. 優先度の高い指摘と出典・根拠・影響
4. 具体的な修正案
5. 残る確認事項と、それによって変わる判断

総合判定は「整合」「修正が必要」「情報不足で判断保留」を使う。確定した重大な不整合があれば「修正が必要」とし、未確認部分を併記する。重要な実行条件が未確認で可否を判断できない場合は「情報不足で判断保留」とする。「整合」は確認できた範囲で実行を妨げる不整合が見つからない場合に使い、完全性の保証にはしない。
